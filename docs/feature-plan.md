# 기능 계획 — 짧은 방명록 (Guestbook)

작성일: 2026-11-06
상태: 계획 확정 (구현 전)

이 문서는 김은지 홈페이지에 추가할 "짧은 방명록" 기능의 명세와 검사 방법을 기록한다.
Notion 허브(김은지 — 홈페이지 프로젝트 기록)에 적힌 포트폴리오/프로필 목표에 맞춰 설계했다.

---

## 1. 다섯 문장 (확정)

1. 내 홈페이지는 국민대 경영정보학과 재학생 김은지를 소개하는 포트폴리오를 위한 곳이다.
2. 방문자는 포트폴리오를 보고 별명과 한 줄 응원 메시지를 남기는 일을 한다.
3. 서버에는 글 고유 번호, 별명, 메시지, 저장 시각을 저장한다.
4. 저장 후 화면에는 방문자들이 남긴 응원 글이 최신순 목록으로 보인다.
5. 친구 휴대폰에서도 같은 글이 보이고 재배포 후에도 기록이 남는 것을 확인하면 완성이다.

---

## 2. 선택한 구성

- 기능: 짧은 방명록 (자유 입력, 로그인 없음)
- 배포: **Netlify** (정적 사이트 + Netlify Functions)
- 데이터 저장소: **Supabase** (Postgres, 공통 필수)
- 프레임워크: 없음 (기존 순수 HTML/CSS/JS 유지)

### Netlify를 고른 이유
현재 프로젝트는 빌드 과정이 없는 순수 정적 사이트다. Netlify는 `netlify/functions/`
폴더에 함수 파일 하나만 두면 `/.netlify/functions/guestbook` 주소로 API가 바로 열려,
기존 구조에 변경을 가장 적게 주면서 서버 기능을 붙일 수 있다. Vercel은 Next.js 같은
프레임워크에서 강점이 큰데 현재는 프레임워크가 없어 Netlify가 더 단순하다.

---

## 3. 화면 설계

현재 `index.html`의 `연락처` 섹션과 `footer` 사이에 "방명록" 섹션을 추가한다.
기존 다크 테마 `.card` 스타일을 재사용한다.

### 입력란·버튼
| 요소 | 내용 | 제약 |
|------|------|------|
| 별명 입력란 | 한 줄 텍스트 | 2~12자 |
| 메시지 입력란 | 한 줄 텍스트 | 1~100자 |
| 등록 버튼 | 클릭 시 서버에 저장 요청 | 저장 중엔 비활성화 |
| 안내 영역 | 상태 메시지 | 로딩 / 성공 / 실패 / 검증오류 |

### 결과(최근 글 목록)
- 페이지를 열면 서버에서 최근 글을 읽어와 최신순 카드로 표시한다.
- 각 글 표시 항목: 별명, 메시지, 저장 시각(예: 2026-11-06 14:30).
- 방문자 입력은 HTML로 실행하지 않고 글자로만 표시한다 (XSS 방지).
  예: `<b>안녕</b>`은 굵은 글씨로 실행되지 않고 입력한 문자 그대로 보여야 한다.

---

## 4. 저장할 데이터 (Supabase 테이블 `guestbook`)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | bigint (자동증가, PK) | 글 고유 번호 |
| `nickname` | text | 별명 (2~12자) |
| `message` | text | 메시지 (1~100자) |
| `created_at` | timestamptz (기본값 now()) | 저장 시각 |

- 실명·연락처는 받지 않는다.

---

## 5. API 설계

| 메서드 | 경로 | 역할 | 요청 본문 | 응답 |
|--------|------|------|-----------|------|
| GET | `/.netlify/functions/guestbook` | 최근 글 읽기 | 없음 | 최신순 글 배열(JSON) |
| POST | `/.netlify/functions/guestbook` | 새 글 저장 | `{ nickname, message }` | 저장된 글 또는 오류 |

### 데이터 흐름
```
브라우저(index.html)
  │  GET  → 최근 글 읽기
  │  POST → 새 글 저장 {nickname, message}
  ▼
Netlify Function (서버, 클라우드에서 실행)
  │  입력 재검증(길이) → Supabase REST API 호출
  ▼
Supabase(Postgres) 테이블 guestbook
```

---

## 6. 성공·실패 동작

### 성공
1. 등록 클릭 → 버튼 비활성화 + "저장 중…" 표시
2. 서버 검증 통과 → Supabase 저장
3. "등록됐어요" 표시 + 목록 맨 위에 새 글 추가 + 입력란 비우기

### 실패 (실패 화면도 결과물의 일부)
- 빈 입력/길이 초과: 요청 전에 "별명 2~12자, 메시지 1~100자로 입력해주세요" 안내
- 서버 검증 실패: 서버가 거절하고 사유 표시
- 네트워크/서버 오류: "저장에 실패했어요. 다시 시도해주세요" + 버튼 재활성화
- 서버 저장이 확인되기 전에는 성공으로 표시하지 않는다.

---

## 7. 접근 제한 (자유 입력 선택에 따른 필수 안전장치)

### 지금 버전에 포함
- 길이 제한을 **서버에서도 재검증** (브라우저 검증만 믿지 않음)
- XSS 방지: 입력을 HTML로 실행하지 않고 글자로만 표시
- 수정·삭제 API를 만들지 않음 (누구나 남의 글을 고치거나 지울 수 없음)
- Supabase 직접 접근 차단: 테이블에 RLS(Row Level Security)를 켜고,
  서버 함수만 사용하는 비밀 키로 저장한다. 브라우저는 서버 함수하고만 통신한다.
- Supabase 키는 브라우저 코드에 두지 않고 Netlify 환경변수에만 저장한다.

### 공개 운영 전 보완 (나중)
- 반복 등록 제한(rate limit), 신고 버튼, 관리자 숨김 기능

---

## 8. 가장 작은 완성 버전 (첫 목표)

한 화면, 한 가지 주요 행동, 저장+조회만 구현한다.
- 방명록 섹션 1개
- 글 등록(POST) 1개
- 최근 글 읽기(GET) 1개
- 수정/삭제 API 없음, 로그인 없음, 신고/관리 기능은 나중.

---

## 9. 검사 방법 (내가 직접 실행해 결과를 남긴다)

"잘 됩니다"라는 답변 대신 아래 항목을 직접 실행하고 결과를 기록한다.

1. **정상 등록**: 별명 "테스트", 메시지 "안녕하세요" 입력 후 등록 → 목록 맨 위에 보이는지 확인.
2. **다른 기기 공유**: 휴대폰 등 다른 기기에서 같은 사이트를 열어 위 글이 보이는지 확인.
3. **재배포 유지**: 사이트를 다시 배포한 뒤에도 글이 남아 있는지 확인.
4. **빈 메시지 거절**: 메시지를 비우고 등록 → 저장되지 않고 안내가 뜨는지 확인.
5. **길이 초과 거절**: 별명 1자 또는 13자, 메시지 101자 입력 → 거절되는지 확인.
6. **XSS 방지**: 메시지에 `<b>안녕</b>` 입력 → 굵은 글씨로 실행되지 않고 입력한 문자 그대로 보이는지 확인.
7. **실패 화면**: 네트워크를 끊거나 서버 오류 시 "저장에 실패했어요" 안내와 재시도가 되는지 확인.

> 주의: 자유 입력은 운영 부담이 있으므로 수업 중에는 시험용 글만 사용한다.
